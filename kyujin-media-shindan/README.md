# 求人媒体適正活用診断アプリ

株式会社JJS オリジナル診断アプリケーション

6つの質問に答えるだけで、貴社の採用条件にもっとも適した求人媒体を
100点満点のマッチ度スコア付きランキングで提案します。
バイトル／バイトルNEXT／マイナビバイトについては、**公式掲載料金表を全エリア・全プラン収録**しています。

---

```
kyujin-media-shindan/
├── index.html              メイン画面（トップ／診断／結果／料金表／モーダル）
├── css/
│   └── style.css           スタイル一式（CSS変数・レスポンシブ・印刷用）
├── js/
│   ├── pricing-data.js     ディップ公式料金データ（PDFから機械生成・手編集禁止）
│   ├── pricing-mynavi.js   マイナビバイト公式料金データ（PDFと全金額突合済み）
│   └── script.js           診断ロジック・媒体データベース・料金表描画
├── tools/
│   ├── build_pricing.py    ディップ料金表PDF → pricing-data.js の生成・検証
│   ├── verify_layout.py    ディップ：文字座標から表を組み直す独立検証

```

サーバーサイド処理・データベース・ビルドは不要です。`index.html` をブラウザで開くだけで動作します。

`index.html` をダブルクリック（同梱の `open-kyujin-media-shindan.cmd` からも起動できます）。

| --- | --- | --- | --- | --- |

| Q2 雇用形態 | `employmentType` | 4 | 複数選択 | 採点30点 |
| Q3 職種カテゴリ | `jobCategory` | 7 | 複数選択 | 採点25点 |

## 診断ロジック（配点）

`js/script.js` の `WEIGHTS` と `calculateMediaScores()` が担当します。

| 項目 | 配点 |
| --- | --- |
| 雇用形態マッチング | 30点 |
| 職種カテゴリマッチング | 25点 |
| ターゲット層マッチング | 20点 |
| 予算マッチング | 15点 |
| 重視ポイントマッチング | 10点 |
| **合計** | **100点満点** |

各項目のスコアは

```
配点 × (その媒体がカバーしている選択肢数 ÷ ユーザーが選んだ選択肢数)
```

で算出し、四捨五入して合算します。つまり「選んだ条件のうち、その媒体が何割満たしているか」を点数化しています。

**計算例**：Q2で「正社員」「アルバイト・パート」の2つを選択し、媒体が正社員のみ対応 → `30 × (1 ÷ 2) = 15点`。

**Q1のエリアは採点に使いません。** 主要媒体はいずれも全国対応であり、
エリアごとの媒体の強さを裏付けるデータを持っていないため、推測で点差をつけることは避けています。
エリアは掲載料金の算出に使います（同じ条件でもエリアで料金が数倍変わるため）。

## 収録媒体（7媒体）

| ID | 媒体名 | 料金の出典 | 主な守備範囲 |
| --- | --- | --- | --- |
| `baitoru` | **バイトル** | ✅ 公式料金表と照合済み | アルバイト・パート／サービス・物流・介護／学生〜30代・女性 |
| `baitoru-next` | **バイトルNEXT** | ✅ 公式料金表と照合済み | 正社員・契約社員／現場職の中途採用／20〜40代 |
| `mynavi-baito` | **マイナビバイト** | ✅ 公式料金表と照合済み | アルバイト・パート＋正社員プラン／サービス業／学生〜20代 |
| `mynavi-tenshoku` | マイナビ転職 | ⚠ 参考値（未照合） | 正社員／全職種／20〜30代 |
| `e-career` | イーキャリア | ⚠ 参考値（未照合） | 正社員／IT・営業・事務／20〜30代 |
| `doda` | doda | ⚠ 参考値（未照合） | 正社員／経験者・即戦力／20〜40代 |
| `woman-type` | 女の転職type | ⚠ 参考値（未照合） | 正社員／女性中心／事務・営業 |

> **料金の信頼度を画面上で区別しています。**
> `pricingVerified: true` の3媒体には「公式料金表と照合済み」バッジ、
> 残り4媒体には「**参考値（公式料金表と未照合）**」の警告バッジを表示します。
> 4媒体の金額は一般的な相場から置いた値で、**出典の裏取りをしていません**。
> 営業資料として使う場合は、各媒体社の最新料金表と照合してから数字を差し替えてください。
> 媒体ごとの守備範囲（対応雇用形態・職種・年齢層・強み）も同様に編集判断であり、
> 実績データに基づくものではありません。

**太字の3媒体は公式料金表データと連動**しており、結果カードの「費用の目安」には
Q1で選んだエリアの料金（ご予算内で使える最上位プラン／そのエリアの最安・最高）が自動算出で表示されます。

各媒体は次のフィールドを持ちます。

```js
'baitoru': {
  name: 'バイトル',
  catch: '...',                  // 1行キャッチ
  features: [/* 特徴5つ */],
  pricing: '...',                // 公式料金データが無い媒体の費用目安テキスト
  priceKey: 'baitoru',           // 任意。dipPricing のキー（あると料金表と連動）
  targetEmployment: ['parttime', 'contract'],
  targetJobs: ['service', 'sales', 'manufacturing', 'medical', 'office'],
  targetAge: ['student', '20s', '30s', 'female'],
  budgetRange: ['low', 'medium', 'high', 'premium'],
  strengths: ['volume', 'speed', 'cost']
}
```

`targetEmployment` / `targetJobs` / `targetAge` / `budgetRange` / `strengths` の値は、
それぞれ Q2〜Q6 のチェックボックスの `value` と同じ文字列を使います。ここが一致していないと採点されません。

> **バイトル／バイトルNEXTの `budgetRange` は起動時に実データから再計算されます**
> `syncDipBudgetRanges()` が全エリア・全プランの実売価格を走査し、
> 「その予算帯で買える掲載が1つ以上あるか」で4帯を自動判定します（結果は4帯すべて）。
> 1枠なら20万円未満（バイトル ¥22,000〜／NEXT ¥36,000〜）で開始でき、
> 上位プラン・複数枠では100万円超（バイトル最大 ¥12,000,000）まで実在するためです。
> 手書きの値が実データとズレることは構造的に起きません。

## 掲載料金データ（バイトル／バイトルNEXT）

### 出所

- 【バ】【2026年1月13日以降】(全国版)バイトル料金表.pdf
- 【社】【2026年1月13日以降】バイトルNEXT掲載料金表.pdf

いずれもディップ株式会社の公式料金表。
**2025年12月1日よりお申込み開始、2026年1月13日ご掲載開始分より適用**（料金は2025年11月時点・すべて税別）。

### 収録範囲

| | バイトル | バイトルNEXT |
| --- | --- | --- |
| エリア | 10エリア | 10エリア |
| 上位プラン | Pプラン(EX)／Pプラン／PLプラン | Pプラン／PLプラン |
| 上位プランの期間 | 7日／14日／1か月 | 14日／1か月 |
| 下位プラン | Dプラン／Cプラン／Bプラン／Aプラン | 同左 |
| 下位プランの期間 | 14日間／1か月／3か月／6か月／12か月 | 1か月／2か月／3か月／6か月／12か月 |
| 枠数 | 上位 1／5／10枠、下位 1／3／5／10／20枠 | 同左 |
| 収録行数 | 各エリア 23行（上段9＋下段14） | 各エリア 25〜26行（上段6＋下段19〜20） |

下位プランの枠数は公式表の行構成をそのまま再現しています。

- **バイトル**：B・Aプランは 1／3／5枠の行が公式表に存在しないため、10／20枠のみを収録。
  また B・Aプランの「14日間」は公式表でも空欄のため、空欄（—）として表示します。
- **バイトルNEXT**：B・Aプランの 1／3／5枠は公式表に「-」の行として存在するため、
  行ごと収録して「—」で表示します（行を省略すると原本と見た目がずれるため）。

エリアは 首都圏／大阪・京都・兵庫／北関東／愛知・岐阜・三重／滋賀・奈良・和歌山／静岡／九州・沖縄／北海道・東北／甲信越・北陸／中国・四国 の10区分。
首都圏・大阪・愛知・九州は市区版（新宿・渋谷・池袋版など）の列も収録しています。

### プランの序列（重要）

公式料金表では**露出度が高い順に上から**並んでおり、その順序は次のとおりです。
**アルファベットは A が最上位ではなく最下位**である点に注意してください。

```
露出度 高  Pプラン(EX) ＞ Pプラン ＞ PLプラン ＞ Dプラン ＞ Cプラン ＞ Bプラン ＞ Aプラン  露出度 低
             （バイトルのみ）
```

アプリの表示順もこの並びに合わせています。
`tools/build_pricing.py` は、PDFの文字座標からプラン名ラベルの上下順を読み取り、
スクリプトの定義と一致しない場合はエラーで停止します（並び順の取り違えを機械的に防止）。

### 主要な金額（税別）

| | 最安（1枠） | 首都圏の最安（1枠） | 最高 |
| --- | --- | --- | --- |
| バイトル | ¥22,000（Cプラン 14日間・静岡ほか4エリア） | ¥38,000（Cプラン 14日間） | ¥12,000,000（Pプラン(EX) 10枠 1か月・新宿・渋谷・池袋版） |
| バイトルNEXT | ¥36,000（Cプラン 1か月・静岡ほか4エリア） | ¥60,000（Cプラン 1か月） | ¥6,400,000（Pプラン 10枠 1か月・新宿・渋谷・池袋版） |

これらの数値はハードコードではなく、`pricing-data.js` から毎回算出しています。

### エリア別の料金算出（結果カード）

`dipRegionSummary(媒体, エリア, 予算帯)` が、Q1のエリアとQ5の予算帯から次の3つを出します。

| 表示 | 内容 |
| --- | --- |
| ご予算内で使える最上位プラン | 予算上限以内で買えるもののうち、**もっとも露出度の高いプラン**。同じプランの中では**最小構成**（そのプランを使い始められる価格）を表示 |
| このエリアの最安 | そのエリアで最も安い掲載 |
| このエリアの最高 | そのエリアの最高額（市区版を含む） |

予算上限は 〜20万円=¥200,000／20〜50万円=¥500,000／50〜100万円=¥1,000,000／100万円〜=上限なし。
複数選択時はもっとも高い帯を採用します。

上位プラン（P系）はエリア内に市区版の列があるため、**基準となる最終列**（例: 首都圏版）を
そのエリアの標準料金として扱い、市区版（新宿・渋谷・池袋版など）は最高額の算出にのみ使います。

**同じ「〜20万円」でもエリアで結果が変わります（バイトルの例）**

| エリア | 最安 | 予算20万円で使える最上位プラン |
| --- | --- | --- |
| 首都圏 | ¥38,000 | Pプラン(EX) 1枠 **7日** ¥133,000 から |
| 大阪・京都・兵庫 | ¥30,000 | Pプラン(EX) 1枠 7日 ¥106,000 から |
| 愛知・岐阜・三重 | ¥26,000 | Pプラン(EX) 1枠 7日 ¥93,000 から |
| 静岡 | ¥22,000 | Pプラン(EX) 1枠 **7日** ¥80,000 から |

同じ最上位プランでも、開始価格が首都圏 ¥133,000 に対し静岡 ¥80,000 と1.7倍違います。
予算を20万円に固定して「買える期間」で見ると、首都圏は7日どまり、静岡なら14日（¥150,000）まで届きます。

### 生成と検証

`js/pricing-data.js` は**PDFから機械生成**しており、手打ち転記は一切ありません。
生成スクリプトは `tools/build_pricing.py` に同梱しています。

```bash
pip install pypdf
cd kyujin-media-shindan/tools
python build_pricing.py "＜バイトル料金表＞.pdf" "＜バイトルNEXT料金表＞.pdf"
```

料金改定時はこのスクリプトを新しいPDFで再実行してください（JSを直接編集しないこと）。
下記の検証に1つでも失敗した場合、スクリプトはファイルを書き出さずに終了します。

1. **プラン名の並び順を座標で検証**
   PDFの文字座標からプラン名ラベルの上下順を取得し、スクリプトの定義と一致するかを全20ページで確認。
   テキスト抽出の順序は表のレイアウトを保証しないため、この検証で「どの行がどのプランか」を確定させています。
   一致しない場合はファイルを出力せずに停止します。
2. **表の抽出と単価の整合**
   PDFのテキストレイヤーから表を抽出し、下位プランの全セルで
   `総額 ÷ 枠数 ÷ 週数 = 公式表記載の「7日／1枠あたり」単価` が成立することを確認
   （2媒体 × 各140行 × 5期間）。
3. **PDF ⇔ 抽出データの金額突合**
   PDF各ページに現れる `¥` 金額の多重集合と、抽出データの値（総額＋再計算した単価）の
   多重集合が完全一致することを確認。全20ページで一致。
4. **座標からの独立再構築との突合**（`tools/verify_layout.py`）
   描画エンジン(pdfium)の文字座標から表を丸ごと組み直し、収録データと突合。
   `build_pricing.py`（テキスト行ベース）とは抽出経路が完全に独立しています。
   20ページ・481行・金額3,395セル・空欄590セル・25,287文字を照合し全一致。
   プラン名と行の対応は「プラン名ラベルのy座標が、その行群の中心と一致するか」で
   幾何的に検証しています。1セルを1円だけ書き換えると検出されることも確認済み。

   ```bash
   pip install pypdfium2
   cd kyujin-media-shindan/tools
   python verify_layout.py "＜バイトル料金表＞.pdf" "＜バイトルNEXT料金表＞.pdf"
   ```

5. **PDFの画像化による目視照合**
   PDFを画像に描き起こし、レイアウトの異なる代表ページ（3列・4列・2列・1列）と
   代表34か所の金額（空欄セルを含む）を目視で突き合わせ。
6. **描画結果の検証**（ブラウザ上）
   全20エリアについて、プランの表示順・行構成・エリア列見出しと、
   描画セル3,985個（金額3,395＋空欄590）の表示値がデータと一致することを確認。
7. **診断ロジックの網羅テスト**
   全2,800通りの単一回答組み合わせで、スコアが0〜100に収まること、
   内訳の合計がスコアと一致すること、降順に並ぶことを確認。
8. **数字が画像で描かれていないことの確認**（`tools/verify_layout.py` の項目J）
   全20ページの画像オブジェクトの位置を調べ、表の範囲に画像が1つも重なっていないことを確認。
   画像はページ下端のロゴと©のみでした。これにより
   **「PDFの文字レイヤー＝実際に目に見える数字」**と断定でき、
   上記1〜7の検証結果がそのまま「見た目との一致」を意味します。
9. **エリア別料金算出のテスト**
   10エリア × 予算6パターン × 2媒体（計120通り）で、最安・最高が矛盾しないこと、
   「予算内で使える最上位プラン」が予算上限を超えず、かつ
   「最上位プランの最小構成」になっていることを確認。
10. **媒体データの整合テスト**
   全7媒体の属性値が実在する選択肢キーのみで構成されていること、
   画面の選択肢とJS側のラベル定義が完全一致すること、
   料金の照合済み／参考値バッジが正しく出し分けられていること（照合済み2・参考値5）を確認。

（うち83セルは比率どおり、10セルは千円単位への切り上げで一致）。
